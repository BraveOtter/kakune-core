# CLI breaking-change migration guide

The canonical CLI now accepts the command paths published in [`AGENTS.md`](../AGENTS.md), standard help, and both version forms. The undocumented alternatives below are rejected by the CLI; they are not hidden aliases. Upgrade scripts that use them before upgrading. A rejected command is a parser error and does not fall through to another Core or local operation.

For Core-backed replacements, select the intended Core with the normal context configuration or `--context <id>`. There is no implicit local fallback. `--data-dir` alone does not select standalone execution. The only direct local workflow execution is `workflow run <workflow> --standalone`.

## Removed paths

| Removed path and former inputs | Former target, output, and side effects | Canonical migration or no equivalent |
| --- | --- | --- |
| `run <file> [--data-dir <dir>] [--standalone]` | Selected Core by default; local only with `--standalone`. Parsed a workflow file, registered or replaced it as enabled, then started execution. Remote output was JSON; local output was TSV. This combined registration, enablement, and execution. | Import, then run: `kakune workflow import flow.yaml` followed by `kakune workflow run id:flow`. Import creates a disabled registration and run does not enable it. Add `kakune workflow enable id:flow` only if trigger eligibility is wanted. For a local-only execution use `kakune --standalone workflow run --file flow.yaml --data-dir isolated-data`; this does not register the workflow. Output and side effects differ. |
| `executions [--data-dir <dir>]` | Local Store by default; explicit context routed to a Core. Printed execution summaries as TSV locally or JSON remotely; read-only. | `kakune execution list [--limit <n>] [--cursor <cursor>] [--json]`. It always observes the selected Core, is paginated, and has a different output shape. |
| `inspect <execution-id> [--data-dir <dir>]` | Local Store by default; explicit context routed to a Core. Printed execution and node details as TSV locally or JSON remotely; read-only. | `kakune execution inspect <execution-id> [--limit <n>] [--cursor <cursor>] [--json]`. It is Core-backed and reports bounded details/availability in a different shape. |
| `auth` | Grouping-only parent; displayed command usage and performed no operation. | No equivalent grouping command. Use only the individual canonical families; there is no canonical CLI for the removed token and pairing operations listed below. |
| `auth recover [--data-dir <dir>] [--config <file>]` | Local Core. Issued replacement administrative access, updated local connection metadata, and revoked previous active tokens. Printed a completion summary; when the OS credential manager was unavailable, the old implementation could display the replacement token once. | No equivalent canonical CLI command. Re-running `init` is not recovery and does not rotate access. If access is lost, use the deployment's existing authorized administrative recovery procedure; do not delete storage or silently replace credentials. |
| `auth pair [--data-dir <dir>] [--config <file>] [--endpoint <url>] [--admin] [--ttl-seconds <seconds>]` | Local Core. Printed an interactive QR invitation, waited for local approval, and could issue a scoped or admin device token. | No equivalent canonical CLI command. The HTTP pairing protocol is a separate API contract; it does not restore the removed interactive CLI workflow. |
| `auth tokens [--data-dir <dir>]` | Local Store. Printed token metadata as TSV without token values; read-only. | No equivalent canonical CLI command. |
| `auth revoke <id> [--data-dir <dir>]` | Local Store. Revoked the selected token and printed confirmation; existing token history remained. | No equivalent canonical CLI command. Do not substitute `init`, which preserves existing access. |
| `storage` | Grouping-only parent; displayed command usage and performed no operation. | No equivalent grouping command. |
| `storage backup <destination> [--data-dir <dir>]` | Local Store. Wrote a consistent backup and printed a JSON summary. Machine-bound secret values were excluded. | No equivalent canonical CLI command. Use the deployment's supported backup procedure; do not copy a live SQLite database as a substitute for a consistent backup. |
| `storage restore <source> <destination>` | Local. Restored a backup to a distinct destination and printed a JSON summary; the destination was created. | No equivalent canonical CLI command. Preserve the source and restore only through a supported storage procedure into an isolated destination. |
| `storage retain [--execution-days <days>] [--event-days <days>] [--artifact-limit-bytes <bytes>] [--data-dir <dir>]` | Local Store. Deleted eligible retained executions/events and unreferenced artifacts, then printed deletion counts as JSON. | No equivalent canonical CLI command. Retention is destructive; do not emulate it with ad-hoc database deletes. |
| `storage compact [--data-dir <dir>]` | Local Store. Checkpointed/compacted SQLite and printed confirmation. | No equivalent canonical CLI command. |
| `storage pin <execution-id> [--value] [--data-dir <dir>]` | Local Store. Changed an execution's retention pin and printed the resulting state. | No equivalent canonical CLI command. |
| `provider upsert <profile.json> [--data-dir <dir>]` | Local Store by default; explicit context routed to a Core. Created or replaced a profile from JSON and printed TSV locally or JSON remotely. | `kakune provider add <id> --file profile.json` covers creation only and rejects duplicates. There is no canonical provider-profile update command; export or preserve the existing profile before planning a manual migration. |
| `provider status <id> [--data-dir <dir>]` | Local Store by default or selected Core. Read the persisted diagnostic and printed TSV/JSON; observational, not a fresh connectivity test. | No exact equivalent. `kakune provider test <id>` performs a bounded active test and can contact the configured provider, so its result and side effects differ from cached status. |
| `provider remove <id> [--data-dir <dir>]` | Local Store by default or selected Core. Deleted the provider profile and printed confirmation/JSON; the referenced secret was not deleted. | No equivalent canonical CLI command. Preserve the profile and separately manage any secret using `secret remove` only when that secret is no longer needed. |
| `provider login <id> [--data-dir <dir>]` | Local Store by default or selected Core. Opened the supported Codex browser authorization flow, replaced the referenced credential, and printed the login/diagnostic outcome. | `kakune provider auth <id>` is the canonical authentication operation for supported providers, but it is not a CLI alias: it targets the selected Core and has its own credential and output contract. |
| `mcp call <call.json> [--data-dir <dir>]` | Local Store by default or selected Core. Read one file containing transport, tool name, and arguments; invoked the one-shot tool and returned JSON. It did not persist a named connection. | `kakune mcp add <name> --file connection.json`, then `kakune mcp tool list <name>` and `kakune mcp tool call <name> <tool> --input args.json`. This persists named configuration, discovers tools, validates input, and uses a selected Core; it is not behaviorally identical. Move secret values to named secret references. |
| `plugin prepare <source> [--data-dir <dir>]` | Local Core Store. Copied/resolved a supported source, performed static inspection without running plugin code, staged it, and printed a review including its digest. It did not activate the plugin. | `kakune plugin install <source> [--approve-digest <reviewed-sha256>]` performs review, explicit approval, validation, and activation as one canonical journey. Staging is internal to this flow; no standalone prepare equivalent exists. |
| `plugin commit <prepared-id> --digest <digest> [--data-dir <dir>]` | Local Core Store. Activated the staged package only when its reviewed digest matched; printed install outcome. | `kakune plugin install <source> [--approve-digest <reviewed-sha256>]` or `kakune plugin update <plugin> [--source <source>] [--approve-digest <reviewed-sha256>]` reviews and approves the exact content. There is no command that commits an old prepared ID. |

## Preserved state and compatibility

Removing these CLI paths does not remove workflows, plugin installations, provider profiles, secrets, credentials, token history, or storage. The upgrade does not run a migration or cleanup just because an old path is invoked. Back up the installation using the deployment's existing supported procedure before unrelated maintenance; do not reset the database to work around a rejected CLI command.

Native service registrations already created by Kakune keep their existing host arguments and fingerprint so the operating system can continue launching the installed service. That host entry is an internal compatibility interface, not a published operator command, is omitted from help and operator examples, and is not a security boundary. Existing ownership and authorization checks remain in force.

## Canonical local-versus-Core routing

- Workflow import/export/list/run/enable/disable and execution, trigger, provider, MCP, secret, and installed-plugin management target the selected Core. An unavailable or unknown selection is an error; the CLI does not fall back.
- `workflow create`, explicit local `workflow validate|plan --file`, and `plugin create` are local authoring/checking operations.
- A workflow file runs locally only with `--standalone`; `--data-dir` by itself does not opt out of Core routing.
- `doctor`, context collection management, and lifecycle controls are local. Service uninstall removes only the native registration and preserves the installation data.
